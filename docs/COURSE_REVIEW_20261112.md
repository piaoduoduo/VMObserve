## 三 原代码包中需要先认清的情况

1. **缺文件。** 第 3.3 项提到的 `pagefault.c` 不在当前代码包；第 4.1 骨架引用的 `child_prog` 也未提供。前者对应栈实验，后者需要按任务自行准备被执行程序。不能把缺失部分写成已经跑通。
2. **很多文件是填空骨架。** fork/exec/wait、pthread、用户级线程、管道、线程通信、生产者消费者、文件与设备 I/O 都留有缺失语句或参数。`fork_exec_wait.c` 还出现 `rintf` 拼写。原文件应保留，补全放到自己的工作副本。
3. **“正确版本”只是输出文字。** `producer_consumer.c` 虽打印这个标题，生产和消费路径的信号量操作仍未填写；是否正确必须看实现和证据。
4. **有些程序故意失败。** 除零、反向持锁、无同步计数、普通共享标志用来观察错误。正常输出一次不能证明并发正确，超时也不能单凭结果断言死锁；还要对照等待关系。
5. **用户级调度要读选择逻辑。** 骨架每次从编号 0 开始找第一个 READY 线程；若 yield 只把自己变回 READY，下次可能仍选自己。要演示交替运行，补上下文操作之外还需明确调度策略。
6. **管道的信号策略影响现象。** 示例 main 忽略 SIGPIPE。补完后无读端的写操作应检查失败返回及 EPIPE，不能照搬“写端会直接被信号终止”的默认情形。
7. **不同打开方式不能混为一谈。** `multi.c` 前两次是独立 open，fork 后子进程又重新 open；不能直接拿这段实验当作“父子进程使用同一个继承描述符时共享文件偏移”的证明。
8. **FIFO 的 EOF 和 EAGAIN 是不同条件。** 非阻塞读时，无写端可返回 0；写端存在但暂时无数据时才是另一种情况。观察前应写出所测试的端点状态。
9. **5.3 不是虚拟内存实验。** 普通共享变量的无同步读写存在 C 语言数据竞争；单凭异常输出不能归因于某一种硬件重排。应按指导书转入原子变量及发布／获取关系。
10. **环境版本需分别记录。** 指导书推荐 openEuler 24.03 LTS，Dockerfile 使用 22.03 LTS；内核模块需要与运行内核对应的构建环境，eBPF 另需 BTF、工具链和权限。当前比赛 VM 已存在，但本轮没有检查这些扩展依赖是否齐全。

以上是静态核查发现，不是本轮编译诊断或运行结果。

课件不能机械套到当前机器，重点解释三处：

- **缺页处理不都需要读磁盘。** 第 60 页图示包含从外存调入，适合解释具有外存后备的场景。匿名内存首次写入可通过内存分配和清零完成；Linux 的 minor/major 计数区分处理是否需要 I/O。当前项目记录这两种计数，应据实解释。[getrusage 接口说明](https://man7.org/linux/man-pages/man2/getrusage.2.html)
- **教学页表结构不是机器配置清单。** 第 57 页采用“中断位 1 表示不在主存”的教学定义，第 63 页又给出 Sv39 的 Valid 位；不能混用位的含义。第 82、96 页包含 32 位地址结构，不能拿图中的位宽和层数当成当前 x86_64 VM 的实测配置。
- **课件结构体是旧实现示意。** 第 107–110 页使用 mmap 链表、vm_next 等字段。上游 Linux v6.6 的 `mm_struct` 已包含 `mm_mt` Maple Tree；课件可用于理解“进程地址空间由区域组成”，但不能照图声称当前 6.6 内核仍使用同一套字段。这里核对的是上游源码，未审计 openEuler 所有发行版补丁。[Linux v6.6 原始定义](https://github.com/torvalds/linux/blob/v6.6/include/linux/mm_types.h)

### 用原任务说明当前改编的差异

原 `malloc.c` 在**同一个进程**中连续申请 1 KiB、256 KiB、1 MiB，观察前面的分配如何影响后面的堆和映射，最后一次释放三块。VMObserve 每种大小启动一个新进程、只申请一块，又增加 16 MiB。当前版本适合隔离比较大小，但没有复现原课例的连续分配过程。

原 `demand.c` 申请 512 MiB，每隔 4096 字节触碰一个位置，累计到四分之一、二分之一和全部。当前版本使用实际基础页大小、缩小内存、校验写入值，并增加释放后的观察。它保留了按需访问问题，但应在课内报告中明确标为改编。原程序注释中的“尚未访问物理内存”也不能当成采样结论：分配器管理信息及其他程序动作可能已触碰少量页。

`malloc` 属于用户态分配器接口；一次调用可以复用已有空间，必要时再通过内核接口取得映射。常见大小阈值是实现策略，不能写成课程定理。当前探针只查询 program break 和 smaps，没有跟踪 brk/mmap 调用；欲确认调用路径，可借第 2.1 项 strace 增加独立证据。[malloc 实现说明](https://man7.org/linux/man-pages/man3/malloc.3.html)

当前 RSS/PSS 的统计对象是与申请范围相交的**整个映射**，不是该 malloc 对象的精确独占占用；缺页计数则是进程范围。这个口径正好可用于教学：先弄清测到了什么，再解释变化。[Linux 6.6 proc 文档](https://docs.kernel.org/6.6/filesystems/proc.html)

## 六 接下来按什么顺序复习
