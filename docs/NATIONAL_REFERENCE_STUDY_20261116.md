# 全国与区域优秀作品研究：VMObserve 下一步应深化什么

研究日期：2026-11-16；比较基线：VMObserve v0.5.0。延续 [11 月 11 日区域赛研究](REGIONAL_COURSE_COMPARISON.md)，扩大到全国功能赛道。本轮取得 6 个公开仓库的全部或部分文件，实际阅读指导书、测试脚本、核心代码和决赛报告相关章节；没有运行这些作品，没有新增本项目 Linux 实验。

## 1. 结论与全国决赛通道

应以全国优秀作品的技术与交付质量为参照，同时按当前第 5 题交付。最需要补的是：**学生能独立完成的实验、可追溯的机制解释、能揭示错误解释的对照、真实使用记录**。已有采集、回放和网页是基础；功能数量、代码行数、报告页数不能替代这些成果。

本轮查看当前区域赛章程物理第 1 页：优秀队伍须经区域技术委员会推荐，并经全国赛技术委员会和大赛组委会审核，才可获得全国赛决赛资格。不是区域一等奖自动晋级。尚未取得推荐名额、对应届次、后续选题与材料转换办法；当前仍按 2026-12-27 提交区域作品。

依据：[区域赛官网](https://os.educg.net/#/index?TYPE=26OS_ZXHNF)、本地 `outputs/2026操作系统中西部华南区域赛-章程.pdf` 第 1 页。当前第 5 题允许聚焦一个课程机制方向，详见 [赛制分析](PROJ5_COMPETITION_ANALYSIS.md)，不直接套用其他届次和赛题的要求。

## 3. 三个主要参考的拆解

### 3.1 F-Tutorials：学生要做成什么，怎样验收

其文件系统实验具有必做与进阶层次，骨架中的 FUSE 回调交给学生实现。测试逐步增加挂载、创建、列目录、卸载及位图、读写、复制等检查。教师验收还包含修改代码、解释真实磁盘布局等问题。

实际定位：

- [学生骨架 myfs.c](https://github.com/F-Tutorials/user-land-filesystem/blob/6c284b89decf0bb4fb2c1803c62f70de9d73008a/fs/myfs/src/myfs.c)：操作回调、必做与选做函数。
- [阶段测试 main.sh](https://github.com/F-Tutorials/user-land-filesystem-test/blob/4be6601beb2b877502e03a70f384b5b277b34c13/tests/main.sh)：按学习进度执行部分测试。
- [位图检查 checkbm.py](https://github.com/F-Tutorials/user-land-filesystem-test/blob/4be6601beb2b877502e03a70f384b5b277b34c13/tests/checkbm/checkbm.py)：读取实际介质结构并输出具体错误。
- [实验概述](https://gitee.com/ftutorials/ftutorials_book/blob/a1c5aa85b2cb70e0f0a46b47a2bcfa065658ac89/Chapter1/1_1.md)、[验收指导](https://gitee.com/ftutorials/ftutorials_book/blob/a1c5aa85b2cb70e0f0a46b47a2bcfa065658ac89/Chapter7/7_1.md)：理论前置、任务层次、现场解释。
- [缓存进阶](https://gitee.com/ftutorials/ftutorials_book/blob/a1c5aa85b2cb70e0f0a46b47a2bcfa065658ac89/Chapter4/4_1.md)：将数据结构、替换策略和观测指标相连，并注明驱动中人为加入延迟的条件。

学校报道记录了课程部署后的学生反馈和多轮迭代；没有给出可转用的教学提升统计。测试与骨架快照为 2022-08，指导书快照为 2022-11，不能把当前指导书全部称作获奖时原稿。

**对我们：** v0.4 已有学生空缺版、参考版和证据绑定笔记，不需要重新建设。主要缺口是学生目前只补一个访问循环，任务深度有限。应增加“修改条件—找证据—解释反例”的分级任务，教师版提供关键回答点及追问。代码动作可以自动检查，理解程度仍需阅读回答或口头验收。

适合下一个课例的问题：三次 malloc 在同一进程执行，为什么与每次新起进程不同？学生应拿出实际调用及映射证据，区分分配器复用与内核新建映射。

**审阅发现：** `checkbm.py` 第 191 行返回三元素列表，第 201 行却用 `if not res2` 检查数据位图；非空列表即使首元素为 False 仍为真，该分支不能按预期识别数量不匹配。这是静态可定位问题，本轮未运行 FUSE 验证。借鉴验收思路，不直接照搬测试实现。

### 3.2 RRAM：课程实验可以有深入的系统实现

RRAM 围绕程序执行贯通模拟器、运行时、操作系统与应用。归档中的 VME 建立地址空间映射，MMU 执行地址翻译，加载器根据 ELF 程序头加载段。报告将课程层次、机制实现和系统演示连接起来。

实际阅读：

- PDF 物理第 5–6 页：PA0–PA4；第 17 页：差分测试；第 21–22、34–37、43、48 页：虚存、分配与加载；第 58–65 页：测试/演示章节的文本与部分截图。报告共 65 页，本轮不是逐页全文审查，9 个相关页另已渲染目视检查。
- [VME](https://github.com/oscomp/first-prize-osf2024-RRAM/blob/8a4ab75ba838c61b9d92c865bae3607efb45e251/abstract-machine/am/src/loongarch/nemu/vme.c)、[MMU](https://github.com/oscomp/first-prize-osf2024-RRAM/blob/8a4ab75ba838c61b9d92c865bae3607efb45e251/nemu/src/isa/loongarch32r/system/mmu.c)、[ELF 加载器](https://github.com/oscomp/first-prize-osf2024-RRAM/blob/8a4ab75ba838c61b9d92c865bae3607efb45e251/nanos-lite/src/loader.c)。
- [架构差分检查](https://github.com/oscomp/first-prize-osf2024-RRAM/blob/8a4ab75ba838c61b9d92c865bae3607efb45e251/nemu/src/isa/loongarch32r/difftest/dut.c)实际比较 32 个通用寄存器；这不能单独证明所有架构状态均已验证。

**对我们：** 将同样的纵向联系聚焦到虚拟内存：源程序地址 → 装载段与映射 → 分配器动作 → 系统调用 → 驻留/缺页 → fork 共享与写入 → 大页条件。每一段都能指向具体代码和观测，是比继续增加孤立图表更有价值的深度。

v0.5 已有地址与 ELF 关联。现在最缺的是原课内 3.2 的同进程连续分配和实际系统调用：仅看映射及 program break，尚不能确认某次 malloc 走了 brk 还是 mmap。

**版本核对：** 官方归档提交为 2024-07-31，不等于最终现场所有改动；PDF 封面写“二零二三年七月”，与 2024 获奖归属不一致，保留原件并注明。README 所称 PR 实际链接到 [NJU 教材 Issue #30](https://github.com/NJU-ProjectN/ics-pa-gitbook/issues/30)，当前为 Open，维护者说明暂未正式支持 LA32，不能说已经合入上游。报告第 36 页的 `unprotect` 功能描述也超过该快照中空函数的实现。我们的最终报告要逐项与交付代码对齐。

### 3.3 MIAYC：诊断必须有对照、有代价分析

代码把程序状态、内存区域及调用栈关联起来，区分错误与警告；分配采样在入口记录上下文、返回时取得地址。测试材料涵盖标准样本、现有工具和开源项目。可借鉴的重点是检验正常情况是否误报、异常是否漏报、优化付出了什么代价。

实际定位：

- [PtrChecker](https://github.com/oscomp/first-prize-osf2025-heap_detection/blob/9832d8a60240701ea0b4800f063fdd9dd6810464/static/src/Checker.cpp)：本轮阅读前 230 行范围中的状态、释放和调用栈处理片段。
- [分配采样](https://github.com/oscomp/first-prize-osf2025-heap_detection/blob/9832d8a60240701ea0b4800f063fdd9dd6810464/system/sampler.bpf.c)：重点读 malloc 入口/返回、事件字段，未全面审计 eBPF 系统。
- [动态决赛测试报告](https://github.com/oscomp/first-prize-osf2025-heap_detection/blob/9832d8a60240701ea0b4800f063fdd9dd6810464/doc/MIAYC-dynamic决赛测试文档.md)第 273–325 行的一组 5016 样本显示：插桩数减少 75.40%，坏样本检出比例同时从基线 89.67% 降至 79.98%。这是作者报告的该组结果，本轮未复现，不代表所有任务的总体效果。
- [统计/复跑脚本](https://github.com/oscomp/first-prize-osf2025-heap_detection/blob/9832d8a60240701ea0b4800f063fdd9dd6810464/static/test/juliet-test/analysis_miayc_report.py)：记录误报、漏报、超时、处理错误，并支持选取误报/漏报文件重跑；必须连同计分口径阅读。
- [静态决赛测试](https://github.com/oscomp/first-prize-osf2025-heap_detection/blob/9832d8a60240701ea0b4800f063fdd9dd6810464/doc/MIAYC-static决赛测试文档.md)开源项目部分：列出工具版本、分析对象和调用位置等信息；“可疑指令”数量不能直接等同于已确认漏洞数。

**对我们：** 为每个诊断建立案例卡：应确认什么、不能确认什么、下一次改变什么。执行成功、解释符合证据、学习者理解，是三种不同验收，不能用一个通过率代替。

**适用性检查：** malloc 返回探针第 136 行跳过大小为 4096 整数倍的分配，而我们的页粒度大块实验常采用这些尺寸。该实现不适合作为我们的完整采样层直接移植。先用阶段标记和系统调用跟踪满足课例；只有明确问题无法回答时再评估内核事件采样。

## 4. 区域教学仓库的补充

movedancer 的报告按知识阅读、代码补全、实验结果组织，适合课内节奏。但其[父子复制关卡](https://github.com/movedancer/OScomp/blob/ff4ebaa4a73c3a793761baaf9a007e1eb5acd5ef/Docs/Exper-Docs/lab3/proj10实训三：第二关.md)第 73 行称实现 COW，同文代码却在复制阶段分配新页并立即 memcpy。截图还引用作者电脑的绝对路径，不能在我们的副本显示。

这说明获奖自述、工程完整性和解释正确性必须分别核对。我们的 COW 保留值隔离和带条件的 PSS 关系，不声称已观察逐物理页复制；正式包中的图片、原始数据和链接也需实际可用。该仓库为 2025-05 快照，不能直接视作 2024 获奖提交原件。

## 5. v0.5 的差距与下一轮验收

| 维度 | 已有基础 | 需要补齐 |
| --- | --- | --- |
| 课程主线 | 地址/ELF、malloc 六阶段、COW、THP、部分课件对齐 | 同进程连续 malloc 和真实调用证据，串联问题顺序 |
| 动手深度 | 学生骨架、参考版、证据绑定笔记 | 分级任务、教师追问、改变条件后的解释 |
| 诊断 | 分级结论、受控 THP 策略对照、原始数据 | 正常反例和证据不足案例，误判审查，明确复验动作 |
| 独立验证 | 两环境真实执行、原文校验、既有 smem 同源解析对照 | 与独立工具或人工读取核对关键结论；同源重解析不算新采样 |
| 教学证据 | 任务页面及资料包 | 首次使用记录、原始回答、真实反馈与修订 |
| 交付 | 历史回放和三种导出 | 设计报告、与原课例的对比、演示、干净环境复现 |

全国样本的赛题与规模不同，以上是内部质量目标，不是官方一等奖分数线，也不能据此推算获奖概率。旧研究中“未找到 PPT”“没有学生骨架”等缺口已由后续工作更新，不再作为当前待办。

### 第一项：v0.6 连续三块 malloc 与调用证据

沿用已有交接确定的下一项，保持 C/Python/本地网页架构和当前主选。

1. 保留原课例同一进程依次申请 1 KiB、256 KiB、1 MiB 的过程，记录块地址、大小、动作和阶段。
2. 保存实际 brk/mmap/munmap 等调用，并与阶段标记关联，记录 libc、页大小和跟踪命令；不按大小预先指定调用类型。
3. 同步保存 maps/smaps，多个块共享 VMA 时不重复累加，解释 free 与实际解除映射的区别。
4. 与独立进程实验对照。工具缺失、跟踪失败分别表达，缺少调用证据时不猜测“已确认”。跟踪开销不用于性能结论。
5. 在既有 WSL 与 openEuler 验证并保存源码、环境、原始跟踪和结果；历史记录不改写。学习者的预测/解释单独记录。

完成标准：能从一个程序动作定位到该阶段的真实调用及映射变化；解释一个 free 后仍驻留的案例，具体行为以当前 libc 实测为准。

### 第二项：机制案例与教学验收

| 案例 | 判断边界 | 对照或追问 |
| --- | --- | --- |
| 小块首次写没有新缺页 | 不能认定按需分配失效 | 同进程/新进程，大块/小块 |
| free 后 RSS 没下降 | 不能据此确认泄漏 | 映射是否保留，后续申请是否复用 |
| fork 未写，RSS 合计增加 | 不能直接说复制了全部物理页 | PSS 合计、写入比例、值隔离 |
| 进程策略禁止 THP | 确认采到的策略状态，配对检验影响 | 仅改变策略，比较驻留及其他条件 |
| THP 未观察到，控制证据缺失 | 原因保持证据不足 | 提出下一项可执行的检查 |
| 原始记录缺失/被构造修改 | 标记证据或校验失败 | 属于人工测试，不当成真实内存异常 |

部分 THP 控制和学生任务已在 v0.4 完成，此处是补统一案例验收。每卡保存来源类别、条件、预期结论、实际输出和差异；程序动作检查与理解评价分开。无需为了数量生成几十个重复案例。

### 第三项：实际使用与最终交付

让真实使用者按 README 在另一份目录或机器首次运行，记录过程与障碍，修订后再复验。团队内与团队外试用如实区分，有多少写多少，不能虚构课程采用或提升率。

报告围绕“课程难点—设计选择—关键实现—正常与反例—同类/原课例比较—反馈与限制”。演示先讲清一个容易解释错的现象，以及怎样凭证据改正，再扩展到 COW 与 THP。主要功能仍以 12 月 15 日冻结为目标，最后阶段集中在复现、材料和讲解。实际试用可随首个完整课例开始，不必等所有功能完成。
