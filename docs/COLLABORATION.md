# VMObserve 接手与协作

## 我们要交付什么

「怎么分都队」参加操作系统设计赛中西部与华南区域赛功能挑战第 5 题「课程实践案例」。作品选华科虚拟内存实验。学生从一个问题开始，沿着程序动作看 Linux 留下的证据，最后用自己的数据解释一次新结果。区域赛交付依据和已核对的提交格式见[赛题分析](PROJ5_COMPETITION_ANALYSIS.md)。

| 学生要学会什么 | 已有实现 | 验收时让学生做什么 |
| --- | --- | --- |
| 3.2 用指针读映射 | 同一进程三次 malloc，六步回放、指针定位、两次 mmap 的边界、按映射求 RSS、重新运行并排比较 | 用自己的 p2、p3 找到各自的原始行。解释为什么两个块能共用一行，算一遍 RSS |
| 3.3 分清申请、首次写入和越界 | 512 MiB 分批触碰六步、原版五次 ps、三种栈条件、实测笔记 | 指出 RSS 首次明显变化在哪一步；分清最后采到的递归层数与内核报告的退出信号 |
| 拓展写时复制与透明大页 | 父子进程八步、改写比例复做；大页四步、两类开关和两种写法 | COW 用父子 PSS 算共享部分；THP 用同次 smaps 的 RSS、AnonHugePages 解释开关两侧差别 |

完整目录保留 7 组 24 项，供同学按指导书查找。7.4 和 7.5 仍是任务说明。当前开发优先级是上述两项重点任务与两项拓展。[课程对照](COURSE_ALIGNMENT.md) · [重点任务](重点任务/README.md)

同伴拿到仓库后，在根目录执行 `python work/launch.py`，用 Python 3.10+ 即可打开本地网页并读取 [6 份内置实测](../examples)。在原开发机跑新实验，先执行 `.\work\vm.ps1 status`。若虚拟机未启动，再执行 `.\work\vm.ps1 start` 和 `.\work\vm.ps1 wait`。复用现有磁盘和 SSH 配置，私钥与磁盘留在本机。[运行方法](../work/RUNNER.md)

## 多个 AI 怎么接力

1. **先选一个学生动作。** 比如「在 COW 末步选一半，点复做，看父子 PSS」。在同一张交接单里写明由谁改什么、用哪份数据验收。开始前看工作区差异，保留其他人还在改的部分。
2. **Gemini 或 Opus 负责学生看到的页面。** 沿用现有美术风格，正文解释动作和结果。改按钮外层布局时，一起核对它的事件处理、状态提示和键盘操作。两位前端协作者一次由一位改同一组件。
3. **Codex 负责后端与前后端联调。** 探针、执行参数、结果字段、诊断、校验与导出由 Codex 维护。需要新的数字时先确认原始文件里有什么，再决定改采集还是改展示。跨边界修复在交接单里标出两端涉及的文件。
4. **验证看改了哪条路径。** 改文案，拿一例原文核对。改复做，实际点一次、看到新编号、对上所选条件并检查报告。只改展示且原始数据没变，可以用已有实测回放。交接中标明「本轮新运行」「历史实测回放」「模拟响应」。
5. **队员用自己的话交付。** 独立试用者照[首次试用单](V071_CLASSROOM.md)做一遍，留下他的判断和卡点。队员分别记录实际贡献和 AI 使用情况；决赛演示与答辩要能当场从页面找到原文。

每次交接留五项即可：**改了什么、涉及文件、怎样复现、看到了什么、下一位做什么**。近期结果见[本轮验收](WORKFLOW_REVIEW_20261120.md)。较早的里程碑见[开发记录](HANDOFF.md)，其中的「下一步」按日期阅读。
