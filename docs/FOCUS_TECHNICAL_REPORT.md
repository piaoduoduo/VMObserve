# VMObserve 参赛技术说明

## 课程任务与设计

作品对应华中科技大学操作系统应用层实验 3.2 连续三次 malloc 和 3.3 按需调页。两项原课例基线、指导书位置、运行编号与复现命令见[参赛基线](FOCUS_BASELINE.md)。课程目标是让学生用程序返回的指针、操作系统观测和受控对照解释内存现象。

3.2 的探针标记每次分配和释放，保存返回地址、`strace` 动作窗口和各阶段 `/proc/self/smaps`。解析器先以半开区间判断指针归属，再按每个存活块的字节范围找出全部相交 VMA。汇总 RSS 时，同一快照内相同起止地址的 VMA 计一次。网页用实测地址生成题目和反馈。基线第三次申请后有 1281 KiB 的存活块、1428 KiB 的相关映射和 16 KiB 的相关映射 RSS。RSS 由两段映射的 4 KiB 和 12 KiB 相加得出。

3.3 的原课例按 4096 字节步长分批写入 A、B、C，保留原来的 malloc 申请方式。受控对照另建 512 MiB 对齐私有匿名映射，访问范围两端留保护页。每一轮运行两个独立进程，只改变 `MADV_NOHUGEPAGE` 与 `MADV_HUGEPAGE`，各轮交替组别先后。保存策略调用结果、地址、`VmFlags`、写入位置数、RSS、匿名大页及进程级缺页增量。解析器用起止地址确认四个活跃阶段采用同一个精确范围，并校验最终读回。进程级对照固定使用 `MADV_HUGEPAGE`，分别解除或启用进程级禁用，并记录开关的实际读回值。

学生在对照页先写下预测，再从两组同阶段原文核对 RSS、匿名大页与次缺页统计范围。练习使用通过校验的配对采样生成答案，可更换阶段或轮次做迁移题。课堂试用可下载本页首次作答，含三项答题与反馈、运行和阶段标识、两组原文哈希。重答的反馈与首次记录分别保留。教师复核页批量读取这些文件，按本机的原报告和原文哈希复算得分，并汇总核对通过的文件。实验报告把观测和解释与运行编号、案例、采样阶段、原文路径及 SHA-256 一起导出，可合并一份已保存的 3.2 笔记。Windows 通过本地 Python 服务回放，Linux 可重新采集。采集器、解析器、原文读取、网页和导出结构共用同一运行记录。

| 环境与记录 | 观察 |
| --- | --- |

| Ubuntu 24.04.5 LTS / WSL2 对照，`20261120T113225.827429Z` | 三轮六个案例通过。四分之一阶段两组各写 32768 个位置，RSS 均为 128 MiB。禁用组的匿名大页为 0 KiB、次缺页 32768 次，请求组为 128 MiB、64 次。 |
| openEuler 24.03 LTS / QEMU TCG 对照，`20261120T120355.446473Z` | 三轮六个案例全部通过。四分之一阶段两组 RSS 均为 128 MiB。禁用组的匿名大页为 0 KiB、次缺页 32768 次，请求组为 128 MiB、64 次。 |
| WSL2 进程级对照，`20261125T110630.221939Z` 与 `20261125T110657.478995Z` | 同一机器各三轮，两组大页建议均返回 0。四分之一阶段两组 RSS 均为 128 MiB，解除禁用组记录 128 MiB 匿名大页、64 次次缺页，进程禁用组记录 0 KiB、32768 次。 |

3.3 回放中的「跨轮核对本步」按当前阶段列出同一运行内各轮的两组读数，并以“使用组减去禁用组”计算配对差的中位数和范围。缺组、校验未通过或阶段不匹配的轮次会标注原因。各指标只汇总两组都有读数的轮次，释放后的映射缺失保留为空值。通用 CSV 的 `count` 保留探针事件字段，`written_positions` 对释放阶段留空，与配对 CSV 的口径一致。

以上单轮和配对结果用于说明本次环境的内存机制。次缺页来自进程级 `getrusage`，驻留来自目标 VMA。建议成功和实际大页驻留分别以 `madvise` 返回值、`VmFlags` 和 `AnonHugePages` 复核。记录中没有大页时，可检查全局策略及采样时机。

## 交付和复核

队内独立审查按[模拟评委量表](COMPETITION_JUDGE.md)记录版本、扣分依据和复验结果。

1. 先按 README 运行 `python -B work/verify_submission.py`，核对九份内置实测。再从首页打开按需调页和写时复制两个采样步骤，对照页表原文。
2. 按[课堂任务与试用记录](FOCUS_TRIAL.md)执行练习。保留真实参与者答案及修改记录。
3. 在另一台设备独立检出并复现。若采用 openEuler，保存内核版本、每组采样结果及报告哈希。openEuler 与 WSL2 的成对记录均已随项目提供。
4. 答辩可用 4 分钟演示。先展示 3.2 手算和原文，再展示 3.3 预测、同阶段差异、策略调用与 `smaps`。最后从进程级同屏对照下载本步证据 JSON，或从笔记区导出学习报告。证据 JSON 保留两个运行编号、阶段、校验哈希和原文路径。评委可使用 `verify_submission.py --process-evidence` 从交付的原始记录重建对照，核对收到的单份文件。
5. 归档技术描述、测试结果、成员实际贡献和 [AI 使用记录](AI_USAGE.md)。正式提交前核对代码及文档许可、官方项目地址和视频链接，保存回执。
