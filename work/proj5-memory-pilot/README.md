## 实际实验与结果

环境为 Ubuntu 22.04.1、Linux 6.6.87.2-microsoft-standard-WSL2、x86_64、4 KiB基础页、GCC 11.4.0。仅对实验内存区域请求关闭透明大页，未改变系统全局设置。最大目标数据页占用约80 MiB，另有程序、页表等开销。

下表是16 MiB实验的结果，三个重复的对应值一致。所有内存值仅指目标区域，单位MiB，未计页表和其他程序开销。

| 阶段 | 父进程RSS | 子进程RSS | 两进程PSS总和 | 当前动作的次缺页增量 |
| --- | ---: | ---: | ---: | ---: |
| 创建区域，未访问 | 0 | — | 0 | — |
| 每页读一个字节 | 0 | — | 0 | 4096 |
| 每四页写一页 | 4 | — | 4 | 1024 |
| 写入全部页 | 16 | — | 16 | 3072 |
| fork后，子进程未写 | 16 | 16 | 16 | 未单独计量fork |
| 子进程改写四分之一页 | 16 | 16 | 20 | 1024 |

64 MiB实验的对应PSS总和为0、0、16、64、64、80 MiB。六次实验均未观察到动作期间的主缺页，目标区域未使用透明大页或发生交换。父子进程的页首字节校验也符合写入后的隔离预期。

RSS会在不同进程中重复计入共享页；PSS按共享者数量分摊页的成本。因此，只把两个RSS相加，会误把fork之后的共享当成完整复制。子进程改写四分之一后，两进程各有4 MiB私有脏页，剩余12 MiB仍共享，PSS合计20 MiB。[Linux官方说明](https://docs.kernel.org/filesystems/proc.html)

读操作产生次缺页但目标RSS仍为0，与Linux匿名内存使用共享零页的机制相符。这是结合接口语义的解释；本轮没有读取物理页帧号，不能把表格称为直接观测到了物理页帧共享。RSS为0也不意味着整个操作没有内存开销。

## 采集方法与局限

`memory_probe.c`使用匿名私有mmap，以两侧保护页隔离目标区域，避免分配器元数据和相邻区域混入。每个阶段读取该区域的smaps，保留完整原文，同时记录RSS、PSS、私有/共享脏页、交换和大页信息。父子进程用管道同步，在采样时暂停目标区域的修改。

动作前后使用getrusage记录缺页增量。该计数属于整个进程，并非目标区域逐页跟踪，检查中允许少量背景缺页。当前精确页数关系只是在本环境、当前访问方式和大页关闭条件下的观测，不能直接推广到任意Linux配置。[getrusage语义](https://man7.org/linux/man-pages/man2/getrusage.2.html)；[MADV_NOHUGEPAGE语义](https://man7.org/linux/man-pages/man2/madvise.2.html)

本轮以mmap隔离内核机制，不等价于完成原课程的malloc实验。正式实现还要解释malloc、分配器复用、brk/mmap与内存释放之间的关系。

## 形成作品的范围

建议独立参赛时集中做好三个实验主题：

1. **分配和首次访问**：未访问、只读、稀疏写、完整写对照，让学生先预测，再运行、查看证据并解释。承接课程的malloc案例，加入直接mmap的受控对照。
2. **写时复制**：改变子进程写入比例，观察共享、复制、值隔离。将RSS误判和PSS解释放在同一实验中。
3. **预期失效的原因**：在openEuler中对比大页策略或内存分配器行为，记录为什么“访问一页就恰好增加一次缺页”的简单判断会失效。不能把偏离预期直接标成程序错误。

实现重点应落在分阶段执行、低干扰采样、测量口径、异常解释和证据复核。界面服务于“源码动作—指标变化—机制解释”的对应关系。内核事件跟踪可作为后续增强，取决于目标环境支持；起步阶段无需把eBPF或修改内核设为必做条件。

完成可用核心后，再做教学验证：邀请少量同学实际使用，记录首次跑通步骤、操作失败原因、理解题前后表现及反馈，并如实报告样本规模。没有完成真实试用前，不声称提升了教学效果。

单人可先负责全部三个主题；招募队友后，优先让另一人承担openEuler复测、独立核验和教学试用，再考虑界面扩展。这样核心进度不依赖能否招到人。
