# 第5题第二轮技术分析与透明大页实验

2026年11月10日。本轮按充分使用AI推进实现、暂不依赖队友配置的前提分析。建议作品定位为“虚拟内存实验观察与诊断工具”：在真实Linux中运行受控实验，根据原始观测解释结果，再通过对照复验验证解释。

## 第二轮实际结果

使用32 MiB、按PMD大页边界对齐的匿名私有映射，比较稀疏写和逐页写，以及MADV_NOHUGEPAGE和MADV_HUGEPAGE。只调整实验进程的目标区域，未改变系统全局设置。四个条件各运行3次，共12次，表内各项在三个重复中一致。

| 访问模式 | 目标区域策略 | 实测RSS | 实测AnonHugePages | 动作期间次缺页 |
| --- | --- | ---: | ---: | ---: |
| 每2 MiB写1字节，共16字节 | 禁止透明大页 | 64 KiB | 0 | 16 |
| 同上 | 请求透明大页 | 32 MiB | 32 MiB | 16 |
| 每4 KiB写1字节，共8192字节 | 禁止透明大页 | 32 MiB | 0 | 8192 |
| 同上 | 请求透明大页 | 32 MiB | 32 MiB | 16 |

“逐页写”指每个基础页写一个字节，并非把32 MiB每一个字节都写满。

环境：Ubuntu WSL2，内核6.6.87.2-microsoft-standard-WSL2，glibc 2.35，基础页4 KiB、PMD大页2 MiB；全局enabled和defrag均为madvise。未对openEuler复测。

本轮支持两个教学判断：相同的稀疏访问，在这两种策略下驻留成本相差512倍；相同的基础页遍历，大页下缺页次数可以显著下降。这不代表性能提升512倍，本轮没有计时或吞吐测量。MADV_HUGEPAGE只是请求，记录以smaps实测结果为准；其他机器可能回退到普通页。

另一个容易误判的细节是：实际使用32 MiB透明大页时，smaps中的KernelPageSize仍显示4 KiB。诊断必须结合AnonHugePages、策略和实际计数，不能只看这一项字段。

依据：[Linux透明大页文档](https://docs.kernel.org/admin-guide/mm/transhuge.html)、[proc及smaps语义](https://docs.kernel.org/filesystems/proc.html)、[madvise](https://man7.org/linux/man-pages/man2/madvise.2.html)。

## 建议的作品范围

保留三个相互关联的实验主题：按需分配与零页、fork后的写时复制、透明大页对观测结果的影响。malloc分配器对照作为课程衔接，优先于增加其他OS子系统。

建议形成四个可验收功能：

1. 分阶段运行和采集：固定动作边界，记录目标映射的原始smaps、操作参数、环境和程序版本。
2. 参数对照：改变读写方式、访问步长、子进程写入比例或大页策略，复验差异。
3. 有依据的诊断：显示支持某种解释的观测、排除项和建议的下一次实验；证据不足时明确显示不能确定，保留大页回退等正常分支。
4. 实验回放与导出：从保存记录重现图表和解释，现场演示不必依赖每次重跑；明确标记实时运行与历史回放。

技术上可采用C实验程序、Python编排与解析、一个本地网页。无需把大模型作为成品的必备运行依赖；AI用于开发不等于工具必须接入在线AI服务。第一版也不需要改内核或部署eBPF。

主要工程难点是目标映射识别、采样时序、跨环境差异、过程计数与映射级指标的区分，以及规则误判。界面负责展示动作、证据和解释，不承担伪造或模拟真实数据的工作。

## 特色如何证明

本项目不以按需分配、写时复制或大页本身作为新发明。特色应落实为课程实验中的观察正确性、受控对照、诊断和复用设计。

例如现场演示：先只给出“写16字节却用了32 MiB”的现象；工具读取大页证据，建议关闭目标区域的大页做对照；复验观察到64 KiB；显示两次完整记录与解释。再展示一个大页请求未实际生效的情况，检查工具是否能报告回退而非强行给出同一结论。后一种情况尚待收集或明确标注的异常路径验证，不能宣称已有真实运行记录。

目前已完成底层可行性观测，诊断模块、界面、openEuler适配和教学试用尚未完成。

同类参照：[上海电力大学2026年获奖项目](https://www.shiep.edu.cn/48/8a/c3154a280714/page.htm)已有多实验教学体系和自动测试。因此应在一个机制方向上做好解释与可复验性，而不以实验数量或页面数量作为主要贡献。现有资料不足以证明全球新颖性或预测本届一等奖概率。

## 文件和运行方式

- `thp_probe.c`：32 MiB受控实验。复用第一轮memory_probe.c中的smaps采集函数。
- `run_thp.py`：编译并执行四个条件，各重复三次。
- `results/summary.json`：环境、源码哈希和汇总数据。
- `results/*.jsonl`及`*.smaps.txt`：程序原始输出和目标区域原始记录。

Linux中执行 `python3 run_thp.py`。依赖GCC和Python3，要求可读proc/smaps以及透明大页尺寸信息。运行会覆盖本轮results；保存多轮数据时先复制结果目录。
