# 课内 3.1 程序地址与映射

先看《第七章 主存管理》9、12、43–49 页，建立虚拟地址和分页概念。106–111 页进一步讨论地址空间中的区域。原 maps.c 打印 PID 并暂停，新探针在自己的进程中保存地址、加载后的 ELF 程序头和完整 smaps。

## 先预测

1. 函数、只读常量、全局变量、malloc 返回的地址、栈局部变量分别需要什么权限？
2. 新进程再次运行同一程序时，这些绝对地址一定相同吗？
3. 知道虚拟地址和所在映射，是否就知道物理页框？

保留自己的答案，再打开页面“程序地址与映射”，点击“运行地址空间实验”。三个新进程各保存一份独立记录。展开“真实对应关系”检查预测；查看旧轮次属于历史回放。

## 对照证据

每个地址用 start <= address < end 定位到 smaps 映射头。r/w/x 是实际读、写、执行权限；p 是私有映射方式。映射头与 RSS 分别回答地址空间和物理驻留问题。

程序与动态库通过 dl_iterate_phdr 读取加载后的 PT_LOAD；运行段起点 = 装载基址 + ELF 段虚拟地址。这里使用程序头中的装载段，不把 ELF 节名与 VMA 作一对一对应。BSS 的零填充尾部可以进入匿名映射，装载器也可能调整映射权限。

选择一条程序函数和一条库函数记录，分别在 JSONL 找到地址与段，在 smaps 找到实际范围和权限。再解释一个跨多条映射的装载段；若当前环境没有这样的段，如实记录。

## 再运行与解释

比较本轮三个进程的函数和栈地址，记录实际相同或不同的部分。权限来自映射，地址变化是否由随机化造成需结合环境条件；本任务不修改系统的随机化设置。

写三句话：我的预测是什么；哪条原始记录支持或修正了它；还不能从这些数据知道什么。程序没有读取物理页框号，也不探测非法写入。相同映射的 RSS 不可按变量重复相加。

命令行入口：Linux `python3 work/run_all.py --suite layout`；Windows `./work/vm.ps1 retest --suite layout`。HTML/JSON/CSV 导出保留地址与映射，JSON/HTML 还包含全部装载段。

实现位置：`work/proj5-course/layout_probe.c`。接口依据：[dl_iterate_phdr](https://man7.org/linux/man-pages/man3/dl_iterate_phdr.3.html)、[proc_pid_maps](https://man7.org/linux/man-pages/man5/proc_pid_maps.5.html)。
